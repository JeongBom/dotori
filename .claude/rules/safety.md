# 안전 규칙

이 프로젝트에서 작업할 때 반드시 지켜야 하는 안전 규칙입니다.

## 절대 금지

- production DB(Supabase)에 직접 마이그레이션 실행 금지.
  스키마 변경은 반드시 SQL 파일로 작성해서 사용자에게 보여줄 것.
- API 키, Supabase 키, 비밀번호를 절대 코드에 직접 작성 금지.
  반드시 .env 또는 환경변수로 관리.
- .env 파일을 절대 git에 커밋 금지.
- 가족 공유 데이터 관련 코드(family_id 사용 코드) 수정 시 RLS 정책 영향 분석 후 진행.

## 가지치기 작업 시 필수

- 기능을 삭제하기 전에 반드시 사용자에게 확인받을 것.
- 삭제할 파일은 한 번에 5개 이상 지우지 말 것.
- 삭제 작업은 항상 새 git 브랜치에서 진행.
- 각 기능 제거 후 앱이 정상 실행되는지 확인 (build 통과 + 핵심 화면 동작).
- 음식 관리, 생필품 관리, 가족 관리 관련 파일은 절대 삭제 대상이 아님.

## v2 작업 시 보호 대상 (절대 삭제 금지)

다음 영역의 코드와 DB 테이블은 v2에서도 핵심이므로 절대 삭제하지 않는다:

- 인증 관련 (auth)
- 가족 관리 (families, users, user_settings 테이블 및 관련 코드)
- 음식 관리 (food_database, fridge_items 테이블 및 관련 코드)
- 생필품 관리 (supplies 테이블 및 관련 코드)

## 삭제 대상 (Phase 1에서 제거)

다음 영역은 v2 컨셉(재고 관리 + 알림)에 맞지 않아 제거 대상:

- 재무/자산 관리 (FinanceScreen, assets/asset_histories/goals/goal_items 관련 코드)
- 일정/집안일 (ChoresScreen, routines 관련 코드)
- 단, DB 테이블 자체는 보존 (CLAUDE.md의 "DB 테이블 구조 > 보존" 항목 참고)

## 의심스러우면 멈춤

작업 중 다음 상황이 발생하면 코드를 수정하지 말고 사용자에게 먼저 확인:

- "이 파일이 삭제 대상인지 확실하지 않다"
- "이 변경이 다른 기능에 영향을 줄지 모르겠다"
- "예상보다 많은 파일을 수정해야 한다"
